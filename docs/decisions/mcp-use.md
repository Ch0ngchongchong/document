# MCP 사용 기록

> **저장 위치:** `docs/decisions/mcp-use.md`

> **사용 방법**
> 1. 우리 팀이 **어떤 일이 필요해서 어떤 MCP를 골랐고**, **공식 문서를 보고 어떻게 설치했고**, **어떤 작업에 썼고**, **내가 직접 무엇을 확인했는지**를 적습니다. "연결했다"는 기록이 아닙니다.
> 2. MCP가 알려 준 것 중 **쓰지 않은 것**(문서 버전이 달랐다, 우리 코드와 맞지 않았다, 화면 결과를 믿지 않았다)을 적습니다. `ai-check-log.md`에도 같은 것을 줄로 남깁니다.
> 3. MCP 결과는 **참고**입니다. 근거는 직접 실행한 결과와 테스트 결과입니다.
> 4. 연결 문제는 **오류 메시지 그대로** 적습니다. 못 고쳐도 괜찮습니다.
> 5. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 작성 시작일: 2026-11-02

## 1. 팀 결정 — 우리 팀에 필요한 MCP

**필요한 일 파악** (`STACK.md`, `PRD.md`, `backlog.md`를 보고 외부 도구가 있으면 좋은 일)

| 필요한 일 | 왜 필요한가 (우리 팀 상황에서) |
| --- | --- |
| Figma 디자인을 화면 코드(React)로 옮기기 | UI 도구가 Figma로 정해져 있고(STACK.md), 사장님·직원 화면을 디자인에서 코드로 옮기는 작업이 이후에 생긴다 |
| 로컬에서 띄운 화면을 열어 직접 확인하기 | React↔FastAPI 업로드→판독 같은 비동기 흐름을 눈으로 확인해야 하는 작업이 있다 (client-meeting-1 피드백 11) |

**후보 비교와 선택** (Claude가 찾아 준 것도 공식 문서·저장소로 직접 확인한 것만 적음)

| 후보 서버 | 공식 문서·저장소 (주소, 절) | 하는 일 | 내 컴퓨터에서 실행되는 명령 | 읽기만 / 쓰기도 | 키 필요 | 고른다 / 보류 / 고르지 않는다 | 이유 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Figma MCP (예시, 공식 문서로 아직 확인 안 함) | 확인 필요 | Figma 디자인 읽어 코드로 변환 | 확인 필요 | 확인 필요 | 확인 필요 | 보류 | 지금은 US-08(상품·단위 정보 등록) CRUD만 만들고 있어 Figma 화면을 코드로 옮길 일이 아직 없다 |
| 브라우저 조작 MCP (예시, 공식 문서로 아직 확인 안 함) | 확인 필요 | 로컬 화면 열어 확인 | 확인 필요 | 확인 필요 | 확인 필요 | 보류 | 오늘 범위(US-08)는 화면이 단순한 CRUD 폼이라 내가 브라우저에서 직접 눌러 확인하는 것으로 충분하다 |

| 항목 | 우리 결정 |
| --- | --- |
| 쓰는 서버 (팀당 1~2개부터. 없으면 "연결하지 않음"과 이유) | **연결하지 않음.** 오늘(US-08) 범위는 LLM 호출도 없고 화면도 단순한 CRUD라 MCP 없이도 충분하다. Figma→코드 변환이나 비동기 업로드 화면 확인처럼 실제로 막히는 작업이 생기면 그때 공식 문서로 서버를 확인하고 다시 연다. 전체 8주 프로젝트로 보면 Figma MCP(화면 6개 반복 변환)와 브라우저 MCP(US-03 비동기 업로드→판독 흐름 확인, client-meeting-1 피드백 11)는 쓸모가 생길 가능성이 높다고 보지만, 지금은 아니고 **US-03(거래명세서 업로드·판독) 작업을 시작하는 시점에 다시 검토**하기로 한다 |
| 설정 위치 | 저장소 `.mcp.json` (키 없음) — 아직 만들지 않음 |
| 승인 방법 | 각자 프로젝트 서버를 읽고 하나씩 승인 (일괄 승인 설정 안 씀) |
| 버전 고정 여부 🔧 | 해당 없음 (연결한 서버 없음) |
| 설치에 쓴 공식 문서 (주소, 절) | 해당 없음 |
| 보류한 서버와 이유 | Figma MCP, 브라우저 조작 MCP — 둘 다 지금 당장 막힌 작업이 없어서 필요해지면 공식 문서를 먼저 확인하고 연결하기로 함 |
