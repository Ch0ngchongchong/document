| 1 | 거래명세서 한 건을 확인하고 입력하는 데 얼마나 걸리나요? (5-5 2번) | 명세서 1장에 약 7분, 기준서는 약 10분 | 4-4 측정 지표 ①의 지금 값이 정해짐 (목표: 절반 이하) |
| 2 | 언제 처리하나요? (5-5 15번) | 마감 후 몰아서 처리 | 판독 요청이 한꺼번에 몰리므로 비동기 처리 필요 |
| 3 | 입력할 때 자주 나는 오류는 무엇인가요? (5-5 1·3·5번) | 박스·낱개 혼동, 한 줄 건너뛰어 누락, 비슷한 상품명 잘못 선택, 수량 오타 | F-04에서 강조할 대상(단위, 빠진 줄, 상품 매칭, 수량)과 단위 환산 규칙 필요 |
| 4 | 직원이 확정해도 되는 경우와 사장님 확인이 필요한 경우는? (5-5 13번) | 직원 확정: 발주한 수량과 들어온 수량이 같은 일반적인 경우. 사장에게 넘김: 발주보다 많이 들어온 경우, 단가가 평소보다 높은 경우, 등록되지 않은 상품이 들어온 경우 | 입고 확인중 → 사장 확인 단계 추가, 변경 이력 저장 |
| 5 | LLM에 JSON으로 보내는 게 좋은가, jev에 보내는 게 좋은가? | 직접 테스트해 봐야 함. 다만 대부분의 AI 모델이 JSON에 익숙하므로 JSON을 권장. jev에 사전 지식을 넣었을 때와 안 넣었을 때 속도 차이가 있음 | LLM 입력 형식은 JSON을 기본으로 하고 비교 테스트 |

| 3 | LLM을 쓰는 이유를 설명할 수 있어야 함. 그냥 글자를 읽어 비교하는 수준이라면 LLM이 필요 없다는 지적. LLM의 강점: 형식이 제각각인 입력을 받아 원하는 형태의 출력을 만들어 냄 | 반영 | 근거 한 문장(3-4 정리)과 OCR+규칙 비교 표, 비교 실험 조건(4-5)을 추가함. 실제 비교 실험은 아직 하지 않음 | 03 3-4 (LLM 역할·OCR+규칙 비교), topic-selection 4-5 |
| 4 | "발주처마다 양식이 다르다"와 "손글씨가 많다"를 LLM을 쓰는 핵심 근거로 내세울 것 | 추가 확인 | 테스트용 명세서로 양식 차이와 손글씨 비율을 확인한 뒤 정함 | |

## 확정된 것 (태그를 [사실]로 올린 항목)
- 거래명세서 1장 처리에 약 7분, 기준서는 약 10분 걸린다 [사실]
- 마감 후 몰아서 처리한다 [사실]
- 자주 나는 오류는 박스·낱개 혼동, 한 줄 건너뛰어 누락, 비슷한 상품명 잘못 선택, 수량 오타다 [사실]
- 수량이 같은 일반적인 입고는 직원이 확정하고, 초과 입고·높은 단가·미등록 상품은 사장에게 넘긴다 [사실]
- 테스트 범위는 카페, 관리 품목 약 150개, 거래처 5곳(식자재 2, 유제품 1, 원두 1, 포장재 1)이다 [사실]
- 주 사용자(사장님)의 평균 연령대는 약 47세다 [사실]
