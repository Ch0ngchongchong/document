# UI 디자인 방향

> **저장 위치:** `docs/DESIGN.md`

> **사용 방법**
> 1. 화면을 만들기 **전에** 화면이 어떤 느낌과 규칙으로 만들어질지 팀이 합의하는 문서입니다. **개발자2가 씁니다**(결정은 팀).
> 2. 색·간격은 **토큰 표**에 한 번만 정하고, 화면에서는 값을 직접 쓰지 않고 이 이름을 씁니다.
> 3. 화면 목록은 PRD의 **기능 ID(`F-xx`)와 연결**합니다. 기능에 없는 화면이나 화면 없는 기능이 없어야 합니다.
> 4. **선택은 팀이 합니다.** Claude는 화면 목록과 기능의 어긋남, 빠진 상태(빈 화면·오류·로딩)를 찾아 주기만 합니다.
> 5. 오늘은 **색 3개, 간격 1개, 화면 목록**까지만 해도 됩니다. 나머지는 `미정`으로 남깁니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

## 방향 한 줄
- 분위기: 시작 화면은 공급처 건물들이 길로 우리 가게와 이어진 아이소메트릭 지도, 매장 안 화면은 흰 배경 위 카드로 내용을 담은 깔끔한 업무 화면. 색은 장식이 아니라 **누가 처리할 차례인지**를 알려 주는 데만 쓴다 — 주황 = 직원이 처리할 차례·확인 필요, 노랑 = 사장님이 처리할 차례, 청록 = 끝남, 빨강 = 반려·오류
  - 지도 장면 (시작 화면에서만, `frontend/src/components/StoreMap.tsx`): 아이소메트릭 일러스트. 매장 안 화면에는 깔지 않는다
    - 색: **우리 가게에만 색(주황)을 쓴다.** 다른 가게(공급처)·상자 더미·길·캐릭터는 모두 무채색(지붕 패널 `#C9CED9`, 선·띠 `#AEB4C2`)
    - 바닥: `background-map` 위에 옅은 아이소메트릭 격자 선(5%)
    - 건물: 흰 덩어리(윗면 흰색, 오른쪽 면 `#E8EBF2`, 왼쪽 면 `#D7DCE6`) + 회색 지붕 패널 격자. 공급처 5곳(식자재 2·유제품·원두·포장재, PRD 1절)과 작은 상자 더미
    - 우리 가게(카페): 가운데에 주황 지붕 + 주황·흰 줄무늬 차양 + 웃는 얼굴. 뒤 바닥에만 은은한 주황 빛(가운데 32% → 바깥 0%)을 깔고, 위에 "우리 가게" 핀(흰 알약 + 주황 테두리·점)을 단다
    - 길: 공급처마다 카페로 이어지는 꺾인 길. 넓은 흰 띠(12px) 위에 가는 회색 선(2.5px) + 길 중간마다 흰 사각 마디(회색 테두리)
    - 캐릭터: 눈 두 개와 회색 띠가 있는 배송 상자 캐릭터가 길을 따라 오간다(11~19초 왕복). '움직임 줄이기' 설정이면 멈춰 있다
    - 화면 전체에 까는 블러 그라데이션 원은 쓰지 않는다
  - 유리 (시작 화면에서 지도 위에 뜨는 것: 로고, 안내 칩, 우리 가게 카드): `surface`(흰색 58%) + 배경 흐림(`glass-blur`: blur 24px, 채도 160%) + 1px 흰 테두리(`glass-border`) + 윗면 흰 하이라이트 + 옅은 그림자
  - 매장 안 화면 배경: 흰색(`background`). 장면·그라데이션 없음. 흰 바탕 위에서 경계가 보이도록 카드 테두리·위쪽 바 아랫줄·탭 트랙 테두리는 옅은 회색 선(`line`)을 쓴다. 카드 안 작은 요소(칩, 아이콘 원, 입력칸, 보조 버튼, 표 머리글)는 `surface-strong`(흰색 78%)
  - 시작 화면 (`frontend/src/pages/StartScreen.tsx`): 앱을 열면 먼저 보이는 화면. 지도 장면을 화면 가득 크게 보여 주고, 우리 가게가 화면 가운데보다 조금 위에 오게 둔다
    - 왼쪽 위에 유리 알약 로고("딱 재고 · 입고 확인 서비스"), 아래 가운데에 유리 안내 칩("주황색 **우리 가게**를 눌러 매장으로 들어가세요", `accent` 점)
    - 우리 가게(카페 + 핀)는 누를 수 있는 버튼이다(마우스·Enter·Space). 마우스를 올리거나 키보드로 고르면 6px 떠오르고, 핀 둘레로 주황 물결이 퍼진다('움직임 줄이기' 설정이면 물결 없음)
    - 누르면 가게 **옆**에 유리 카드가 열린다(폭 320px, 좁은 화면에서 오른쪽에 자리가 없으면 가게 **아래**). 카드: `MY STORE` 라벨 + 닫기(×, 48px) + 매장 이름(26px, 굵게) + "사장님 · 거래처 5곳과 연결 ›"(`accent` 점, 높이 48px 버튼) + 주요 버튼 **[우리 매장으로 가기 →]**(카드 폭 가득). 열리면 이 버튼에 키보드 초점이 가고, 카드가 열린 동안 가게 뒤 주황 빛이 조금 넓어진다
    - 카드 열림·닫힘: 열릴 때 0.2초 동안 왼쪽 8px에서 제자리로 오며 나타나고(투명도 0 → 1, 끝에 느려지는 곡선), 닫힐 때는 정확히 거꾸로 0.2초 동안 왼쪽 8px로 밀리며 사라진다(처음에 느린 곡선). 닫기(×)·Esc·**카드 밖 배경 클릭**으로 닫힌다. 우리 가게를 다시 누르거나 카드 안을 누르면 닫히지 않는다. '움직임 줄이기'면 애니메이션 없이 바로
    - 거래처 목록: "거래처 5곳과 연결"에 커서를 올리거나(키보드로 고르거나 눌러도) 카드 오른쪽에 유리 목록이 열린다(폭 300px, 오른쪽에 자리가 없으면 카드 아래). 위에 "연결된 거래처 N곳"(숫자 `accent`), 줄마다 회색 상점 아이콘(36px) + 이름 + "분류 · 배송 요일" + ›(높이 56px 버튼). 많으면 목록 안에서 스크롤(최대 높이 260px). 카드와 목록 사이를 지나가도 바로 닫히지 않게 0.18초 기다린다. 이름을 누르면 그 거래처 페이지로 간다
    - [우리 매장으로 가기]를 누르면 매장 화면(공통 틀 + 상품 목록)으로, 거래처 이름을 누르면 거래처 페이지로 들어간다. 매장 화면의 로고나 경로의 "홈"을 누르면 시작 화면으로 돌아온다
    - 화면 전환 애니메이션 (지금은 **꺼 둠**, `App.tsx`의 `SLIDE_ENABLED`): 켜면 시작 화면 → 매장 화면에서 매장 화면이 오른쪽 밖에서 1초 동안 등속으로 들어오고, 왼쪽에 붙은 주황 차도(폭 300px, 높이 = 화면, 양쪽 가장자리에서 20px 안쪽 흰 실선 4px + 가운데 흰 점선 중앙선 6px·36px 간격)와 그 위의 배달 트럭(폭 280px, 화면 세로 가운데, 왼쪽을 봄, 위아래 10px·0.5초씩 들썩임)이 함께 들어온다. 뒤의 시작 화면은 왼쪽으로 12% 밀리며 85% 밝기로 어두워진다. 돌아갈 때는 정확히 거꾸로(매장 화면이 오른쪽으로 빠지고 트럭은 오른쪽을 봄). 트럭은 운전석 쪽이 차도 끝에 붙고 반대쪽에 20px 여유를 둔다. '움직임 줄이기'면 바로 바뀐다
  - 공통 틀 (매장 안 모든 화면, `frontend/src/components/AppShell.tsx`): 흰 배경 + 화면 위에 고정된 위쪽 바(`surface` + 흐림 + 아랫줄 `line`). 왼쪽에 주황 사각 로고(40px, 모서리 12px) + "딱 재고" + 매장 이름(누르면 시작 화면으로 가는 버튼), 가운데에 화면 탭, 오른쪽에 알림 아이콘 원 + 사용자 칩(검정 원 아바타 + 역할, **폭 112px 고정** — 사장님/직원으로 바뀌어도 탭이 흔들리지 않게)
    - 화면 탭: 옅은 회색 트랙(`track` 바탕 + `line` 테두리) 안의 알약 버튼 탭(높이 48px). 지금 화면은 흰 바탕 + `text` 글자 + 앞에 `accent` 점 + 옅은 그림자, 다른 탭은 `text-muted`(마우스를 올리면 `text`). 탭은 8개, 순서: 상품 · 발주 · 명세서 업로드 · **거래처** · 입고 확인 · 예외 승인 · 입고 달력 · 변경 이력. PRD 5절 화면 6개 + 거래처·입고 달력(PRD 밖, 시안). 모두 누를 수 있다(`frontend/src/components/screens.ts`). 거래처 상세 페이지에서도 거래처 탭이 켜져 있다
    - 사용자 칩: 지금 화면을 쓰는 사람(사장님 / 직원)을 보여 준다. 직원 화면(명세서 업로드·입고 확인)은 본문 16px·버튼과 입력칸 48px, 나머지는 사장님 화면 크기(18px·56px)
    - 좁은 화면(900px 미만): 탭은 둘째 줄로 내려가 가로로 밀어 보고, 사용자 칩은 숨긴다
  - 본문: 가운데 정렬, 최대 폭 1280px. 카드 사이 간격 16px
  - 카드: `surface` 바탕 + 1px `line` 테두리 + 옅은 그림자 + 둥근 모서리 16px(`radius-card`). 카드 머리에는 주황 선 아이콘 + 제목(20px, 굵게) + 한 줄 설명(`text-muted`), 오른쪽 끝에 검정 알약 칩(기간 `7일` 또는 개수 `3개`)
  - 제목: 굵은 큰 제목(34px)만 둔다(제목 위 영문 라벨은 쓰지 않는다) + 아래에 경로. 숫자가 든 한 줄 요약(예: "확인을 기다리는 명세서가 3건 있어요")은 쓸 수 있는 화면에서 넣는다
  - 경로: `홈 › 화면 이름`(거래처 상세는 `홈 › 거래처 › 거래처 이름`). 단계마다 누를 수 있는 버튼(글자 15px, 누르는 영역 48px) — "홈"은 시작 화면으로, 나머지는 그 화면으로 간다. 지금 화면은 `text` 굵게, 나머지는 `text-muted`, 마우스를 올리면 `accent` + 밑줄
  - 상태 요약 칩: 공간을 덜 차지하도록 작게 줄여 **폼·목록 카드 바로 위**에 한 줄로 둔다(제목 옆에 두지 않는다). 흰 바탕 + `line` 테두리 + 모서리 10px, 왼쪽에 상태 색 사각 아이콘(26px, 모서리 7px, 흰 상태 아이콘 14px) + 이름(14px, `text-muted`) + 굵은 숫자(16px). 상태 이름이 있는 칩은 아래 '상태값별 색·아이콘'을 따른다 (예: `발주 초안 1`, `입고 대기 1`, `등록 상품 3`)
  - 요약 숫자 카드 줄: 화면 위에 숫자 카드 2~4개를 한 줄로 둔다(좁으면 아래로 쌓임). 카드는 작은 이름(`text-muted`) + 오른쪽 위 아이콘 원(40px, `line` 테두리) + 큰 숫자(32px, 굵게) + 단위(작게) + 아래에 설명 한 줄 또는 미터
    - 점 미터: 점 12개(14px)로 비율을 보여 준다. 채운 점 `accent`, 빈 점 `track` (예: 환산값 등록 2/3)
    - 막대 미터: 높이 14px 둥근 막대. 채운 부분 `done`, 빈 부분 `track` (예: 기준 단가 등록 2/3)
    - 시간에 따라 바뀌는 값은 변화(좋아지면 `done`, 나빠지면 `danger`) + 오른쪽에 작은 추이 그래프(최근 값만 `accent`, 나머지는 회색)
    - 숫자는 서버에서 받은 목록을 세서 만든다. 화면이 숫자를 지어내지 않는다
  - 목록 + 입력 폼 배치: PC(1024px 이상)에서는 목록(1.7) | 입력 폼(1) 두 열로 나란히 놓고, 폼 칸은 한 열로 쌓는다. 그보다 좁으면 위아래로 쌓는다
  - 상태 막대: 입고 검수 건 상태는 위가 둥근 굵은 세로 막대(모서리 22px)로 보여 준다. 빈 트랙은 옅은 회색, 채운 부분은 상태 색, 건수는 막대 안 아래쪽에 흰 글자
  - 버튼: 주요 버튼은 알약 모양 검정(`primary`), 마우스를 올리거나 키보드 포커스가 가면 `accent`로 바뀐다. 보조 버튼은 흰 바탕 + `line` 테두리. 바로가기 버튼은 지름 52px 검정 원 아이콘 + 아래 이름
  - 표: 머리글은 작은 `text-muted` 글자 + 위에 고정, 줄 사이는 1px `line`. 첫 열(코드·번호)은 `accent` 굵은 글자, 줄 hover는 옅은 주황. 상태는 아래 '상태 캡슐'. 발주와 다른 줄 수가 1 이상이면 `accent` 굵은 글자. 좁은 화면에서는 표만 가로로 밀어 보고 페이지는 넘치지 않는다. 표 칸 글자와 상태 캡슐은 한 줄로 두고(줄바꿈 없음), 좁으면 표만 가로로 민다. 예외: 입고 확인 표는 힌트·품목 후보가 여러 줄로 내려갈 수 있고, 발주 표의 공급처·품목 칸은 줄바꿈을 허용한다(최소 7rem). 발주 번호 아래에 작성일을 작은 `text-muted` 글자(13px)로 붙인다
  - 상태 캡슐: 점 대신 **상태 아이콘(16px)** + 이름. 모서리 10px, 상태 색 옅은 바탕 + 상태 색 글자(14px, 굵게). 아이콘은 아래 '상태값별 색·아이콘' 표를 따른다. 상태가 아닌 캡슐도 같은 모양(예: 상품 표 `warning` 경고 세모 "환산 확인 필요" / `done` 체크 원 "정상", 예외 종류 `owner` 경고 세모, 변경 이력 종류 `muted` 시계)
  - 그래프: 선 2px 둥근 끝 + 아래로 옅어지는 영역, 목표선은 `done` 점선 + 끝에 "목표 3.5분" 이름. 시간대 분포는 둥근 사각형 히트맵(많을수록 진한 `accent`)
  - 입력칸: 모서리 14px, 포커스 시 `accent` 테두리 + 옅은 주황 링. 여러 줄 입력칸(사유)도 같은 모양

## 모든 화면에 있어야 하는 상태
| 상태 | 어떻게 보이나 |
| --- | --- |
| 빈 화면 (데이터 없음) | 카드 안 목록 자리 가운데에 `primary` 원형 아이콘 + 짧은 문장 + 다음 행동 버튼 1개를 보여 준다. 카드 틀과 제목은 그대로 둔다 (예: 상품 목록이 비었을 때 "아직 등록한 상품이 없어요" + [상품 등록], `업로드 대기` 건이 없을 때 "올릴 명세서가 없어요"). 상태 막대에서 0건인 단계는 빈 트랙 + `text-muted` "0건" |
| 오류 | 무엇이 안 됐는지 문장으로 보여 주고 상태는 그대로 둔다. 화면 오류는 위쪽에 진한 빨강(`danger-strong`) 바탕 + 흰 글자의 둥근 알림(`radius-control`) + 문장, 입력칸 오류는 칸 테두리를 `danger` 색으로 바꾸고 칸 아래에 `danger` 색 글자로 적는다. 카드 하나의 데이터를 못 불러오면 그 카드 크기는 유지하고 가운데에 `danger` 작은 점 + "불러오지 못했어요"(`text-muted`) (예: 사진·PDF가 아닌 파일 → "사진이나 PDF 파일만 올릴 수 있어요", 업로드되지 않고 `업로드 대기` 그대로, US-03 / 판독 실패 → `업로드 대기`로 돌아가고 다시 올려 달라는 알림, US-03) |
| 불러오는 중 | 데이터를 불러오는 동안 숫자·그래프 자리에 옅은 회색 둥근 막대(스켈레톤)를 보여 주고, 카드 크기는 바꾸지 않는다 (돌아가는 아이콘은 쓰지 않는다). 판독은 `판독 중` 상태 알약(`info`)을 보여 주며, 첫 데모에서는 단순 폴링으로 상태가 바뀌었는지 다시 확인한다 (STACK.md 예상 어려움과 대응) |
| LLM 결과를 사람이 확인하기 전 | `직원 확인 대기` 화면의 판독 결과는 "확정 전 초안"으로 표시하고, 재고 수량은 바뀌지 않은 값을 보여 준다 (US-03·US-04 LLM 조건). `uncertain_fields`와 규칙 검증 실패 칸은 추측값 없이 빈칸으로 강조하고, 확인되지 않은 강조 칸이 남아 있으면 확정할 수 없다 (US-03, US-04, 03 3-4 안전장치). 위쪽에 진한 빨강(`danger-strong`) 바탕 + 흰 글자의 둥근 배너 "AI가 읽은 초안이에요. 확인한 뒤 확정해 주세요"를 띄우고, 강조 칸은 `warning` 배경에 "확인 필요" 라벨을 붙인다(색만으로 구분하지 않고 라벨 글자를 함께 쓴다). 확인할 칸이 남아 있으면 확정 버튼을 끄고 "확인할 칸 3개 남음"처럼 남은 개수를 보여 준다 |
