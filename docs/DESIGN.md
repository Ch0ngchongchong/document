# UI 디자인 방향

> **저장 위치:** `docs/DESIGN.md`

> **사용 방법**
> 1. 화면을 만들기 **전에** 화면이 어떤 느낌과 규칙으로 만들어질지 팀이 합의하는 문서입니다. **개발자2가 씁니다**(결정은 팀).
> 2. 색·간격은 **토큰 표**에 한 번만 정하고, 화면에서는 값을 직접 쓰지 않고 이 이름을 씁니다.
> 3. 화면 목록은 PRD의 **기능 ID(`F-xx`)와 연결**합니다. 기능에 없는 화면이나 화면 없는 기능이 없어야 합니다.
> 4. **선택은 팀이 합니다.** Claude는 화면 목록과 기능의 어긋남, 빠진 상태(빈 화면·오류·로딩)를 찾아 주기만 합니다.
> 5. 오늘은 **색 3개, 간격 1개, 화면 목록**까지만 해도 됩니다. 나머지는 `미정`으로 남깁니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

## 방향 한 줄
- 분위기: 사장님 화면(F-02 발주, F-06 예외 건 승인)은 사장님 평균 연령대 약 47세에 맞춰 글자·버튼을 크게 하고 조작 단계를 줄인다 (client-meeting-1 피드백 12, mvp-scope.md)
  - 사장님 화면: 본문 18px, 버튼 높이 56px
  - 직원 화면: 본문 16px, 버튼 높이 48px
  - 모든 화면: 누를 수 있는 영역은 48px 이상, 한 화면에 주요 버튼(`primary`)은 1개만 둔다
- 참고 서비스 (캡처 없이 이름만): 토스, 토스플레이스 (큰 글씨, 넓은 여백, 한 화면에 한 가지 일)
- 반응형: 필요 (모바일 화면 폭 기준: 360px). 태블릿 768px·PC 1024px 이상에서는 표를 넓게 보여 준다. 명세서 촬영·검수는 모바일, 사장님 검토는 태블릿·PC (client-meeting-1 피드백 13 "추가 확인")

## 모든 화면에 있어야 하는 상태
| 상태 | 어떻게 보이나 |
| --- | --- |
| 빈 화면 (데이터 없음) | 목록 자리 가운데에 아이콘 + 짧은 문장 + 다음 행동 버튼 1개를 보여 준다 (예: 상품 목록이 비었을 때 "아직 등록한 상품이 없어요" + [상품 등록], `업로드 대기` 건이 없을 때 "올릴 명세서가 없어요") |
| 오류 | 무엇이 안 됐는지 문장으로 보여 주고 상태는 그대로 둔다. 화면 오류는 위쪽에 `danger` 색 띠 + 아이콘 + 문장, 입력칸 오류는 칸 테두리를 `danger` 색으로 바꾸고 칸 아래에 `danger` 색 글자로 적는다 (예: 사진·PDF가 아닌 파일 → "사진이나 PDF 파일만 올릴 수 있어요", 업로드되지 않고 `업로드 대기` 그대로, US-03 / 판독 실패 → `업로드 대기`로 돌아가고 다시 올려 달라는 알림, US-03) |
| 불러오는 중 | 데이터를 불러오는 동안 로딩 표시를 보여 준다. 판독은 `판독 중` 상태를 그대로 보여 주고, 첫 데모에서는 단순 폴링으로 상태가 바뀌었는지 다시 확인한다 (STACK.md 예상 어려움과 대응) |
| LLM 결과를 사람이 확인하기 전 | `직원 확인 대기` 화면의 판독 결과는 "확정 전 초안"으로 표시하고, 재고 수량은 바뀌지 않은 값을 보여 준다 (US-03·US-04 LLM 조건). `uncertain_fields`와 규칙 검증 실패 칸은 추측값 없이 빈칸으로 강조하고, 확인되지 않은 강조 칸이 남아 있으면 확정할 수 없다 (US-03, US-04, 03 3-4 안전장치). 위쪽에 `warning` 배너 "AI가 읽은 초안이에요. 확인한 뒤 확정해 주세요"를 띄우고, 강조 칸은 `warning` 배경에 "확인 필요" 라벨을 붙인다. 확인할 칸이 남아 있으면 확정 버튼을 끄고 "확인할 칸 3개 남음"처럼 남은 개수를 보여 준다 |
