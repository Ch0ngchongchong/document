## US-01 발주 작성·승인·전달

**매장 사장님으로서, 필요한 상품과 수량을 골라 발주를 작성·승인하고 공급처 전달 완료로 표시하고 싶다. 왜냐하면 무엇을 얼마나 주문했는지가 남아 있어야 입고 때 명세서와 대조할 수 있기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-02
- 경로: 정상
- 관련 상태 전이: 발주 초안 → 발주 확인 완료 → 공급처 전달 완료 → 입고 대기
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 사장님이 상품과 수량(1 이상)을 골라 저장하면 `발주 초안` 상태의 발주 건이 만들어진다
- [ ] (정상) 사장님이 `발주 초안`을 승인하면 `발주 확인 완료`가 되고, 공급처 전달 완료로 표시하면 `공급처 전달 완료` → `입고 대기`가 된다
- [ ] (정상) 발주 건이 `입고 대기`가 되면 연결된 입고 검수 건이 `업로드 대기` 상태로 1건 만들어진다
- [ ] (정상) 발주 작성·승인·전달 어느 단계에서도 재고 수량은 바뀌지 않는다 (R3)
- [ ] (실패·거절) 수량이 0 이하이거나 등록되지 않은 상품이 있으면 저장되지 않고 상태는 그대로다
- [ ] (실패·거절) 한 상품의 수량이 정해 둔 한도를 넘으면 승인 전에 경고가 뜨고, 다시 확인해야 `발주 확인 완료`가 된다 (R7)
- [ ] (권한) 직원은 발주를 승인하거나 전달 완료로 바꿀 수 없다
- [ ] (권한) 다른 매장 사용자는 이 발주를 조회할 수 없다

### 미확정
- 사장님 화면 기준: 평균 연령대 약 47세에 맞춘 큰 글씨·버튼, 단순한 조작 단계의 구체 수치(client-meeting-1 피드백 12)

## US-02 공급처 전달 전 발주 취소

**매장 사장님으로서, 공급처에 보내기 전의 발주를 취소하고 싶다. 왜냐하면 잘못 작성했거나 더 이상 필요 없는 발주가 입고 대기로 넘어가면 안 되기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-02
- 경로: 취소·반려
- 관련 상태 전이: 발주 초안 → 발주 취소
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 사장님이 `발주 초안` 상태의 발주를 취소하면 상태가 `발주 취소`가 된다
- [ ] (정상) 취소된 발주에는 입고 검수 건이 만들어지지 않고 재고도 바뀌지 않는다
- [ ] (실패·거절) `공급처 전달 완료` 또는 `입고 대기` 상태의 발주는 취소할 수 없고 상태가 그대로다
- [ ] (권한) 직원은 발주를 취소할 수 없다
- [ ] (취소·반려 스토리) 매장 사장님이, 공급처에 전달하기 전(`발주 초안`)에 취소하면 `발주 취소`로 가고, `발주 취소`는 끝 상태라 다른 상태로 바뀌지 않는다

### 미확정
- `발주 확인 완료` 상태(승인 후, 전달 전)에서도 취소할 수 있는지 (5-2는 '보내기 전'이라고만 적혀 있음)

## US-03 거래명세서 업로드·판독

**매장 직원으로서, 거래명세서 사진·PDF를 올리면 품목·수량·단위·단가·금액이 공통 형식의 표로 정리되길 원한다. 왜냐하면 지금은 명세서 1장을 확인·입력하는 데 약 7분이 걸리고, 마감 후 몰아서 처리하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 정상 (판독 실패 시 재업로드 포함)
- 관련 상태 전이: 업로드 대기 → 판독 중 → 직원 확인 대기 / 판독 중 → 업로드 대기 (판독 실패)
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 직원이 `업로드 대기` 건에 거래명세서 사진 또는 PDF를 올리면 상태가 `판독 중`이 된다
- [ ] (정상) 판독이 끝나면 `직원 확인 대기`가 되고, 각 줄이 품목명·규격·수량·단위·단가·금액과 품목 후보(최대 3개, 고른 이유 포함)로 표시된다
- [ ] (정상) LLM이 확신하지 못한 값(`uncertain_fields`)과 규칙 검증 실패 칸(수량×단가≠금액, 줄 금액 합≠합계)은 추측값 없이 빈칸으로 강조 표시된다
- [ ] (정상) 판독 건마다 LLM 입력·출력 토큰 수, 호출 비용, 업로드부터 `직원 확인 대기`까지 걸린 시간이 판독 로그에 남는다
- [ ] (실패·거절) 사진이 흐리거나 잘려 판독에 실패하면 상태가 `업로드 대기`로 돌아가고 직원에게 다시 올려 달라는 알림이 간다
- [ ] (실패·거절) 사진·PDF가 아닌 파일은 업로드되지 않고 상태는 `업로드 대기` 그대로다
- [ ] (권한) 다른 매장 사용자는 이 명세서와 판독 결과를 볼 수 없다
- [ ] (LLM) 판독 결과가 나와도 재고는 바뀌지 않고, 상태는 직원이 확정할 때까지 `직원 확인 대기`에 머문다
- [ ] (LLM) 거래처 담당자 이름·연락처·사업자 정보는 직원 기기 안에서 가린 뒤 보내며 LLM 요청에 포함되지 않는다. 원본 사진은 외부 LLM으로 보내지 않는다

### 미확정
- '불확실한 값'으로 표시할 확신도 기준 수치 (표본 테스트 후 결정, 03 3-4 안전장치)
- 온디바이스 OCR 여부와 처리 시간 (구현 방식 비교 후 결정)
- 업로드 → 대기열 → 판독 → 결과 알림 비동기 구조 채택 여부 (client-meeting-1 피드백 11)

## US-04 발주·납품 대조 및 일반 건 확정

**매장 직원으로서, 판독 결과와 발주 내용을 나란히 보고 다른 줄과 불확실한 값을 고친 뒤 확정하고 싶다. 왜냐하면 박스·낱개 혼동, 줄 누락, 비슷한 상품명 오선택, 수량 오타가 자주 나기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상
- 관련 상태 전이: 직원 확인 대기 → 재고 반영 완료 (일반 건)
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) `직원 확인 대기` 화면에 판독 결과와 발주 내용이 줄 단위로 나란히 보이고, 품목·수량·단가가 다른 줄이 강조된다
- [ ] (정상) 직원이 확정한 내용이 발주와 모두 같으면(일반 건) 상태가 `재고 반영 완료`가 되고 확정 수량(기준 단위)만큼 재고가 늘어난다
- [ ] (정상) 직원이 확정한 내용에 수량 차이·파손·단가 변경·발주에 없는 품목이 하나라도 있으면(예외 건) `사장 승인 대기`가 되고 재고는 바뀌지 않는다
- [ ] (실패·거절) 강조된 칸(불확실한 값, 규칙 검증 실패, 품목 후보 없음 또는 후보 2개 이상)이 하나라도 확인되지 않았으면 확정할 수 없다
- [ ] (실패·거절) 상품 목록과 매칭되지 않은 줄은 자동으로 연결되지 않고, 직원이 기존 상품을 고르거나 새 상품으로 등록해야 확정할 수 있다 (R9)
- [ ] (실패·거절) `재고 반영 완료`가 된 건은 직원이 다시 수정할 수 없다 (재고 조정으로 따로 처리)
- [ ] (권한) 다른 매장 사용자는 이 입고 검수 건을 볼 수 없다
- [ ] (LLM) 직원이 확정하기 전에는 판독 결과가 재고에 반영되지 않고 상태는 `직원 확인 대기`이다
- [ ] (LLM) 해당 없음 — 이 단계에서는 LLM을 호출하지 않는다 (보내지 않을 정보는 US-03)

### 미확정
- 직원 화면 기기 (모바일 촬영과 같은 기기에서 검수하는지, 다음 미팅 확인)

## US-05 단위 환산 및 수량 검증

**매장 직원으로서, 명세서의 박스·묶음·낱개 단위가 기준 재고 단위로 자동 환산되길 원한다. 왜냐하면 박스·낱개 혼동이 가장 흔한 입력 오류이기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-05 (F-01 단위 정보 사용)
- 경로: 정상
- 관련 상태 전이: 없음 (직원 확인 대기 안에서 수행)
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 환산값이 등록된 상품이 박스 단위로 적혀 있으면 기준 재고 단위로 환산해 보여 준다 (예: 박스당 24개, 2박스 → 48개)
- [ ] (정상) 확정되면 재고에는 환산된 기준 단위 수량이 반영된다
- [ ] (실패·거절) 환산값이 등록되지 않았거나 단위를 알 수 없으면 자동 환산하지 않고 그 줄을 '확인 필요'로 강조하며, 직원이 수량을 직접 입력해야 확정할 수 있다
- [ ] (권한) 다른 매장에 등록된 환산값은 적용되지 않는다

### 미확정
- 기준 재고 단위를 박스와 낱개 중 무엇으로 할지, 상품마다 다른지 (R6, 5-5 Q11)
- 한 명세서에 박스·낱개가 섞여 적혀 있을 때 구분하는 방법 (R6)
- 공급처가 박스 구성을 바꿨는데 환산값이 갱신되지 않은 경우의 처리 (R6)

## US-06 예외 건 사장 승인·반려

**매장 사장님으로서, 발주보다 많이 들어왔거나 단가가 평소보다 높거나 등록되지 않은 상품이 들어온 입고 건을 확인해 승인하거나 반려하고 싶다. 왜냐하면 이런 경우는 직원이 혼자 확정하면 안 되기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-06
- 경로: 취소·반려
- 관련 상태 전이: 직원 확인 대기 → 사장 승인 대기 → 승인 → 재고 반영 완료 / 사장 승인 대기 → 반려 → 직원 확인 대기 또는 검수 종료 / 사장 승인 대기 → 직원 확인 대기 (직원 확정 취소)
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 예외 건이 `사장 승인 대기`가 되면 사장님 화면에 예외 종류(초과 입고·높은 단가·미등록 상품 등)와 직원이 적은 예외 사유·사진이 보인다
- [ ] (정상) 사장님이 승인하면 `승인` → `재고 반영 완료`가 되고, 승인된 수량·단가로 재고와 매입 단가가 반영되며, 모자란 수량은 발주 건에 미입고로 남는다
- [ ] (실패·거절) 직원이 예외 사유를 적지 않으면 예외 건을 확정할 수 없다
- [ ] (실패·거절) 사장님이 반려 사유를 입력하지 않으면 반려되지 않고 상태는 `사장 승인 대기` 그대로다
- [ ] (권한) 직원은 예외 건을 승인하거나 반려할 수 없다
- [ ] (취소·반려 스토리) 사장님이 사유를 입력해 반려하면 `반려`가 되고 재고는 바뀌지 않는다. 이후 직원이 재검수하면 `직원 확인 대기`로, 사장님이 공급처에 반품·정정을 요청하고 닫으면 `검수 종료`로 간다
- [ ] (취소·반려 스토리) 사장님이 처리하기 전이면 직원이 확정을 취소해 `직원 확인 대기`로 되돌릴 수 있고, 사장님이 승인·반려한 뒤에는 직원이 확정을 취소할 수 없다
- [ ] (취소·반려 스토리) `검수 종료`된 건은 다시 열 수 없고, 다시 납품되면 새 입고 검수 건을 만든다

### 미확정
- '평소보다 높은 단가'의 판정 기준 (몇 % 초과인지)
- 사장님 검토 기기 (태블릿 또는 PC, 다음 미팅 확인)

## US-07 입고 변경 이력 조회

**매장 사장님으로서, 누가 언제 어떤 값을 어떤 값으로 바꿨는지 보고 싶다. 왜냐하면 재고가 맞지 않을 때 판독·수정·승인 과정을 되짚어 볼 수 있어야 하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-07
- 경로: 정상
- 관련 상태 전이: 없음 (판독·수정·검수·승인·재고 반영 시 기록)
- LLM 관여: 아니오
