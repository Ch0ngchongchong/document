# API 약속 (화면과 서버가 주고받는 것)

> **저장 위치:** `docs/API.md`

> **사용 방법**
> 1. 오늘은 **오늘 만든 기능 하나의 항목만** 씁니다. 전체 API는 다음 차시 이후에 채웁니다. 개발자1과 개발자2가 **구현하기 전에 같이 읽고 약속**하는 문서이기도 합니다.
> 2. 항목의 **입력·출력·실패 응답**은 `backlog.md`의 **인수 조건**과 `decisions/first-feature.md` 2절에서 가져옵니다. 인수 조건에 없는 응답을 새로 만들지 않습니다.
> 3. 필드 이름·상태값은 `DATA-MODEL.md`와 **똑같이** 씁니다.
> 4. 이 문서는 **공유 파일**입니다. PM만 고치고, 바꿀 일이 있으면 PR 댓글로 요청합니다. 개발자1과 개발자2가 합의한 약속을 PM이 옮겨 적습니다.
> 5. 모르는 것은 `미정`으로 씁니다. 임의로 정하지 않습니다.
> 6. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 최종 수정일:
- 근거: `backlog.md`, `DATA-MODEL.md`, `../document/docs/decisions/first-feature.md`

## 공통 규칙
| 항목 | 내용 |
| --- | --- |
| 응답 형식 | [제안] JSON. 성공 시 데이터 객체(또는 목록)를 그대로 돌려준다 |
| 오류 응답 형식 | [제안] `{"error": {"code": "<원인 코드>", "message": "<사람이 읽는 설명>"}}` |
| 인증·권한 | 로그인 방식 미정. [제안] 첫 기능에서는 요청 헤더 `X-User-Id`에 시드 사용자 ID를 넣고, 서버가 그 사용자의 `store_id`·`role`을 사용한다. `store_id`는 요청 본문으로 받지 않는다 |

## 항목 1: 상품·단위 정보 등록 (기능 ID: F-01 / 스토리: US-08)

> 경로·HTTP 상태 코드는 인수 조건에 없어 **[제안]**으로 적었습니다. 개발자1·개발자2가 합의하면 [제안] 표시를 지웁니다.

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | [제안] `POST /products` |
| 입력 | `product_code`, `name`, `spec`, `base_unit`, `pack_unit`, `conversion_qty`, `base_unit_price` (DATA-MODEL.md 상품 필드). `store_id`는 입력으로 받지 않고 로그인한 사용자의 매장으로 정한다 [제안]. 어느 필드가 필수인지는 미정 (DATA-MODEL.md 미정 표) |
| 출력 (성공) | 저장된 상품 1건 (위 필드 + 상품 ID). 상품 목록에 추가되고 이후 판독의 품목 후보 대상이 된다 |
| 실패 응답 | 저장되지 않는다. ① 같은 매장에 `product_code`가 이미 있음 — [제안] `DUPLICATE_PRODUCT_CODE` ② 필수값이 비어 있음 — [제안] `REQUIRED_FIELD_MISSING`. 어느 필드가 필수인지 미정(DATA-MODEL.md 미정 표)이며, 필수 필드가 정해지기 전에는 이 실패 응답을 테스트하지 않는다 ③ `conversion_qty`가 0 이하 — [제안] `INVALID_CONVERSION_QTY`. HTTP 상태 코드는 [제안] ①②③ 모두 `400`이고, 원인은 공통 규칙의 오류 응답 형식 `code`로 구분한다 |
| 권한 (누가 못 하나) | 다른 매장 사용자는 이 매장의 상품 목록을 볼 수 없다 (목록 조회 권한은 항목 1-2 참고). 직원도 상품 정보를 등록·수정할 수 있는지는 미정 (backlog US-08 미확정) |
| 바뀌는 상태 | 없음 (기준 데이터, 상태 전이 없음) |
| 관련 인수 조건 | `decisions/first-feature.md` 2절 번호 미정 (2절이 아직 비어 있음). backlog US-08 인수 조건: (정상) 등록 저장 / (실패·거절) 코드 중복·필수값 빈칸·환산값 0 이하 / (권한) 다른 매장 조회 불가 |
| 화면이 쓰는 곳 | 상품 목록·등록 (사장님) — 저장 버튼 |

### 입력·출력 예시
> 값은 DATA-MODEL.md 시드 #2(가상 값)입니다. 응답 모양은 공통 규칙의 응답 형식이 정해지면 맞춥니다.
```
요청:
POST /products
{
  "product_code": "P-0123",
  "name": "서울우유 1000ml",
  "spec": "1L",
  "base_unit": "개",
  "pack_unit": "박스",
  "conversion_qty": 10,
  "base_unit_price": 2650
}

응답(성공):
{
  "id": 1,
  "store_id": 1,
  "product_code": "P-0123",
  "name": "서울우유 1000ml",
  "spec": "1L",
  "base_unit": "개",
  "pack_unit": "박스",
  "conversion_qty": 10,
  "base_unit_price": 2650
}

응답(실패): conversion_qty가 0일 때 — 저장되지 않음 ([제안])
400
{
  "error": {
    "code": "INVALID_CONVERSION_QTY",
    "message": "환산값은 0보다 커야 합니다"
  }
}
```

## 항목 1-2: 상품 목록 조회 (기능 ID: F-01 / 스토리: US-08)

> 경로·응답은 인수 조건에 없어 **[제안]**으로 적었습니다. 개발자1·개발자2가 합의하면 [제안] 표시를 지웁니다.

| 항목 | 내용 |
| --- | --- |
| 요청 (경로·방식) | [제안] `GET /products` |
| 입력 | 없음. 로그인한 사용자의 매장 상품만 돌려준다 [제안] (공통 규칙 인증·권한 참고) |
| 출력 (성공) | 이 매장의 상품 목록 (항목 1 출력과 같은 필드) |
| 실패 응답 | 없음 [제안] — 다른 매장 상품은 오류가 아니라 목록에 나오지 않는다 |
| 권한 (누가 못 하나) | 다른 매장 사용자는 이 매장의 상품 목록을 볼 수 없다 (US-08 권한) |
| 바뀌는 상태 | 없음 (조회만) |
| 관련 인수 조건 | backlog US-08 (정상) "저장하면 상품 목록에 추가되고" / (권한) 다른 매장 사용자는 이 매장의 상품 목록을 볼 수 없다 |
| 화면이 쓰는 곳 | 상품 목록·등록 (사장님) — 목록 표시 |
