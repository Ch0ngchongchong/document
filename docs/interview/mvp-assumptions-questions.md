# 5. MVP 가설, 기능 목록, 가정·위험, 클라이언트 질문지, 미팅 준비

> 목표: 우리가 만들 것과 모르는 것을 목록으로 만들고, 모르는 것을 클라이언트가 답할 수 있는 질문으로 바꾼다.

## 5-1. MVP 가설

> 클라이언트 미팅 전 우리의 추측입니다. 미팅 뒤 바뀔 수 있습니다. 제안서 Ⅰ-3 제안 범위, Ⅳ-10 목표 흐름의 바탕이 됩니다.

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 흐름 1개 (첫 데모에서 보여 줄 것) | 사장님이 상품과 수량을 넣어 발주를 만들고 승인한다 (발주 초안 → 발주 확인 완료) → 공급처에 보냈다고 표시한다 (→ 공급처 전달 완료) → 공급처가 접수하면 입고를 기다린다 (→ 입고 대기) → 물건이 오면 직원이 거래명세서 사진을 올리고, 화면에 정리된 품목·수량을 실물과 대조해 고친 뒤 확정한다. 확정한 수량만큼 재고가 늘어난다 (→ 입고 완료). 되돌림 경로: 공급처에 보내기 전이면 사장님이 발주를 취소한다 (발주 초안 → 발주 취소). 근거: 3-2 상태 전이, 4-1 후보 A |
| 이 흐름에서 LLM이 쓰이는 곳 | 입고 대기 → 입고 완료 단계. 거래명세서 사진·PDF를 읽어 상품명·수량·단가 표로 바꾸고, 발주 내용과 다른 줄을 표시한다 (3-4 L1). LLM은 재고를 바꾸지 않고, 직원이 확정 버튼을 눌러야만 재고가 바뀐다. 거래처 담당자 이름·연락처는 LLM에 보내기 전에 가린다 |
| 당장 제외할 것과 이유 | ① 판매량 예측·발주 수량 추천 (3-4 L2, 후보 C): 판매 기록이 쌓여야 하고 예측이 맞는지 첫 데모 안에 확인하기 어렵다. 발주 수량은 사장님이 직접 넣는다 ② POS 연동으로 판매 시 재고 자동 차감 (후보 B): 외부 POS마다 연동 방식이 달라 시간이 오래 걸린다 ③ 공급처에 문자·앱으로 자동 발주 전송: 공급처마다 주문 방식이 다르다 (2-2 순서 5). '공급처 전달 완료'는 사장님이 버튼으로 표시한다 ④ 부분 입고·반품 (3-1 R3, R4)과 공급처의 취소 승인·거절 경로: 공급처 화면까지 필요해서 핵심 흐름이 돈 다음에 붙인다 |

## 5-5. 클라이언트 질문지

> 카테고리마다 1개 이상, 총 8~10개. 미팅 질문 시간은 팀당 약 12분이므로 우선순위 1~5번은 반드시 묻는 질문입니다. **1~3번은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 질문을 고칠 때 팀원끼리 서로 읽어 보고 예/아니오로 끝나거나 답을 유도하는 질문을 고칩니다.

> 좋은 질문의 조건: ① 예/아니오로 끝나지 않는다 ② 구체적인 사례를 들어 묻는다 ③ 우리 해결책을 정답으로 유도하지 않는다 ④ 답을 들으면 무엇을 결정할지 알고 있다.

## 5-6. 미팅 역할 분담

> 실제 클라이언트 미팅에서 다섯 명이 하나씩 맡습니다. [팀 역할](../team/roles.md)과 따로 정해도 됩니다.

| 역할 | 하는 일 | 담당 |
| --- | --- | --- |
| 진행자 | 질문 순서·시간 관리, 꼬리 질문 | 신은총 |
| 기록자 | 답변을 말 그대로 기록 | 김가은 |
| 꼬리 질문자 | "예를 들면요?", "그 경우 누가요?"로 파고들기 | 진수화 |
| 시간·가정 체커 | 남은 시간을 알리고, 미팅에서 확인된 가정을 표시 | 권기범 |
| 요약·확인자 | 끝나기 1분 전, 들은 답을 3문장으로 되읽어 클라이언트에게 맞는지 확인 | 김지운 |

## 5-7. 미팅 전에 다시 볼 것

> 제안서를 보낸 뒤 미팅까지 팀이 함께 확인합니다.

| 확인할 것 | 메모 |
| --- | --- |
| 클라이언트가 제안서 Ⅶ-18의 고객사 설정을 어떻게 정해 올지 예상해 보고, 답에 따라 바뀌는 질문 | 매장 종류와 상품 수, 거래명세서 샘플·상품 목록, POS나 공급처 연동이 필요한지 정해 올 수 있다. 샘플이 있으면 상품명이나 단위가 상품 목록과 다른 사례를 묻는다. 샘플이 없으면 언제 받을 수 있는지, 테스트용 자료를 줄 수 있는지 확인한다. POS나 공급처 연동이 꼭 필요하면 첫 데모 범위를 다시 잡는다. |
| 제안서 Ⅶ-16의 `[가정]` 중 틀리면 MVP가 크게 바뀌는 것 |  |
| 클라이언트가 상태 흐름이나 LLM 역할을 바꾸자고 하면 우리가 지킬 것과 양보할 것 | 지킬 것: 직원이 확인하고 확정하기 전에는 재고를 바꾸지 않는다. LLM은 거래명세서를 읽고 다른 점을 표시하는 데까지만 쓰고, 수량 계산과 상태 변경은 규칙과 사람이 맡는다. 조정할 것: 첫 데모에서 읽을 거래명세서 형식과 항목을 줄이고, 공급처 전달·접수는 사람이 표시한다. 부분 입고·반품, 공급처 취소 승인, POS·공급처 연동은 핵심 흐름을 확인한 뒤 정한다. |
| 제안서에 쓰지 않았지만 질문받으면 답해야 할 것 (근거 카드 번호) | 판독이 틀리거나 발주 수량과 다르면 직원이 직접 고친 뒤 확정한다. 확정 전에는 재고가 바뀌지 않는다 (3-4 L1). 부분 입고와 불량 반품은 첫 데모에서 빼고, 다음 범위를 정할 때 3-1 R3·R4를 참고한다. 수요 예측·자동 발주·POS 연동도 첫 데모에는 넣지 않는다 (5-1, 3-4 L2). 관련 근거 카드: 1-shusbox-2, 4-shusbox-1. |
