# 4. 문제 후보 평가와 세부 주제 확정

> 목표: 이전 조사에서 나온 문제 중 8주 동안 풀 하나를 근거를 들어 고른다.

## 4-1. 문제 후보 3개

> As-Is 흐름의 문제 지점(2-2)과 규칙 표(3-1)에서 고릅니다. 후보마다 ⑤ 문제와 손해에서 찾은 근거(카드 번호)를 붙입니다.
> 같은 도메인의 다른 팀과 겹치지 않아야 합니다. 예약·대여 주제는 고르지 않습니다.

| 후보 | 누구의 문제인가 | 어떤 문제인가 (한 문장) | 근거 (표 이름, 카드 번호) |
| --- | --- | --- | --- |
| A | 매장 사장님 | 종이 거래명세서를 보고 입고된 상품과 수량을 일일이 손으로 입력하다 보니, 누락이나 오타가 생겨 재고 기록이 틀어진다. | 1-shusbox-2 |
| B | 매장 사장님 | 판매된 수량을 직접 파악해 재고를 수동으로 갱신하다 보니, 판매 기록과 실제 재고가 맞지 않는다. | 5-shusbox-3 |
| C | 매장 사장님 | 재고가 안전재고 아래로 떨어져도, 곧 입고될 상품인지 정말 품절인지 구분하지 못해 품절을 늦게 알아채고 판매 기회를 놓친다. | 5-shusbox-3, 4-shusbox-1 |

## 4-2. 필수 조건 확인

> 점수를 매기기 전에 먼저 거릅니다. **두 칸 중 하나라도 비면 그 후보는 점수표에 올리지 않습니다.** 셋 다 걸러지면 후보를 바꾸거나 범위를 넓혀 다시 찾습니다.

 후보 | 상태 전이: 핵심 대상과 상태 흐름 (4개 이상, 취소·반려 경로 포함)                                                                                                                                                                                                   | LLM: 서비스 안에서 하는 일과 사람이 확인하는 곳 | 통과 |
| --- |--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------| --- |------|
| A | 입고 건: 입고 대기 → 명세서 판독 → 입고 확인중 → 입고 완료 (수량 부족·파손 → 부분 입고 → 공급처 누락 문의 / 검수 중 불량 → 반품 → 반품 완료, 반품 수량만큼 재고 차감)                                                         | 거래명세서 사진·PDF를 읽어 상품명·수량·단가 표로 바꾸고 발주 내용과 다른 줄을 표시한다. 매장 직원이 입고 확인 화면에서 실물과 대조해 고친 뒤 확정해야만 재고가 바뀐다. | ☑   |
| B | 재고 조정 건: 차이 감지 → 실사 요청 → 실사 완료 → 조정 승인 → 재고 반영 (실사 수량이 틀리면 반려 → 재실사). 단, 3-2에서 조사한 대상이 아니라 근거 없이 세운 흐름이다                                                                                 | 판매 수량은 POS의 숫자 데이터라 규칙으로 계산하면 되고, 3-4에 이 문제에 맞는 LLM 후보가 없다. | ☑     |
| C | 발주 건: 발주 초안 → 발주 확인 완료 → 공급처 전달 완료 → 입고 대기 → 입고 완료 (초안에서 사장님이 취소 → 발주 취소 / 전달 후 취소 요청 → 공급처 승인 시 발주 취소, 거절 시 입고 대기). '입고 대기' 상태로 곧 들어올 상품과 진짜 품절을 구분한다. | 시스템이 계산한 추천 발주 수량의 근거(판매 추이·날씨·요일)를 쉬운 말로 설명하고, 공급처별 주문 메시지 초안을 쓴다. 사장님이 수량을 고치고 승인해야 발주가 전송되며, 초안 속 숫자는 시스템이 계산값과 대조해 다르면 막는다. | ☑   |

## 4-3. 선정 기준 점수표

> 필수 조건을 통과한 후보만 각 항목 1~3점으로 매깁니다. 총점이 같으면 ①과 ⑤를 우선합니다.

| 기준 | 무엇을 보나 | A 거래명세서 입력 | B 판매 재고 갱신 | C 안전재고·입고예정 구분 |
| --- | --- | --- | --- | --- |
| ① 규칙의 명확성 | 규칙을 글로 쓸 수 있고, 테스트로 확인할 수 있는가 | 3 | 3 | 2 |
| ② 경계 사례 | "이 경우엔요?"가 3개 이상 나오는가 | 3 | 3 | 3 |
| ③ 상태·권한 | 상태 전이가 분명하고, 사용자별 권한 차이가 있는가 | 3 | 2 | 3 |
| ④ 외부 접점 | 외부 데이터나 시스템과 닿는 지점이 하나 이상 있는가 | 2 | 2 | 2 |
| ⑤ 8주 MVP 가능성 | 우리 팀 인원으로 3주차에 핵심 흐름 1개를 돌릴 수 있는가 | 2 | 2 | 2 |
| ⑥ LLM의 쓸모 | LLM이 없으면 사람이 오래 걸리는 일을 줄이는가, 틀렸을 때 걸러 낼 수 있는가 | 3 | 2 | 2 |
| ⑦ 팀의 흥미 | 팀원들이 설명하고 싶어 하는 문제인가 | 2 | 2 | 3 |
| **합계** | | **18** | **16** | **17** |

**점수 근거**

- **A:** ① 발주 내용과 명세서를 대조하고 직원이 확정하는 규칙이 분명하다(3). ② 부분 입고·파손·누락·품목 불일치 등 경계 사례가 3개 이상이다(3). ③ 입고 대기부터 완료까지 상태와 직원 확인 권한이 제시돼 있다(3). ④ 거래명세서와 공급처 문의가 외부 접점이지만 연동 방식은 미정이다(2). ⑤ 단일 입고 확인 흐름은 시연할 수 있으나 명세서 양식과 판독 정확도가 확인되지 않았다(2). ⑥ 수기 판독·입력을 직접 줄이고 직원이 결과를 확인한다(3). ⑦ 첫인상 조사에서 한 팀원이 수기 입력 문제를 언급했지만 팀 전체 선호는 확인되지 않았다(2).
- **B:** ① POS 판매량과 실사 수량의 차이를 계산하고 승인 후 조정하는 규칙은 테스트할 수 있다(3). ② 누락 판매·반품·파손·실사 오류 등 경계 사례를 다룰 수 있다(3). ③ 실사→조정안→승인/반려→재고 반영 흐름은 가능하지만 4-2에 새로 세운 흐름이라 권한과 근거가 덜 구체적이다(2). ④ POS 연동이 외부 접점이나 연동 방식은 미정이다(2). ⑤ POS 자료 연결과 실사 확인이 필요해 핵심 흐름의 초기 구현 가능성을 중간으로 봤다(2). ⑥ LLM이 직원의 차이 사유 메모를 분류·요약해 조정 사유 초안을 만들고, 직원이 확인하는 활용안을 전제로 했다. 수량 계산은 규칙으로 처리하므로 LLM의 기여는 보조적이다(2). ⑦ 첫인상 조사에서 수기 재고·입력 문제가 나왔으나 팀 전체 선호는 확인되지 않았다(2).
- **C:** ① 안전재고 기준은 있으나 입고 예정 정보를 언제·어떻게 반영할지 규칙이 더 필요하다(2). ② 입고 지연·취소 승인/거절·부분 입고·안전재고 도달 등 경계 사례가 충분하다(3). ③ 발주 초안부터 입고 완료까지 상태와 사장님·공급처의 권한이 제시돼 있다(3). ④ 공급처 응답과 판매·날씨 정보가 외부 접점이지만 데이터 확보 방식은 미정이다(2). ⑤ 핵심 흐름은 정할 수 있지만 실제 입고·판매 데이터 연결 범위가 불확실하다(2). ⑥ LLM 설명과 메시지 초안은 발주를 돕지만, 입고 예정과 품절의 구분 자체는 시스템 규칙·데이터에 달려 있다(2). ⑦ 팀 첫인상에 수요 예측, 과잉 재고, 폐기 우려가 여러 번 나왔다(3).

총점은 A 18점, C 17점, B 16점이다. A가 가장 높지만 A와 C의 차이는 1점이다. ④·⑤ 점수는 외부 연동과 실제 데이터 확보가 확인되지 않은 상태를 반영했다. B의 LLM 점수는 3-4에 이미 적힌 후보가 아니라 위에 제안한 활용안에 대한 평가다.

## 4-4. 문제 정의서 (선정한 후보)

> 4-1~4-5가 제안서 Ⅲ 세부 주제 선정 과정의 바탕이 되고, 이 표는 Ⅰ 제안 개요와 Ⅱ 현황 분석에도 쓰입니다.

| 항목 | 내용 |
| --- | --- |
| 프로젝트 가제목 | 사진 한 장 입고: 거래명세서를 읽어 주는 매장 입고 확인 서비스 |
| 문제 문장 | "소규모 매장 사장님은 공급처에서 물건이 들어올 때 종이 거래명세서의 품목과 수량을 손으로 옮겨 적어야 하기 때문에, 누락·오타 없이 재고 기록을 맞추는 데 어려움을 겪는다." |
| 주 사용자 | 매장 사장님 (입고 확인과 재고 기록을 직접 함). 직원이 있는 매장은 직원이 입고 확인을 맡고, 사장님은 결과와 부분 입고·반품 건을 본다 (2-1) |
| 지금은 어떻게 해결하고 있나 | 거래명세서를 보며 입고된 상품과 수량을 엑셀에 한 줄씩 입력한다 (2-2 순서 2). 박스히어로 같은 재고 앱은 바코드로 입출고를 기록할 수 있지만, 명세서와 발주 내용을 대조하는 일은 여전히 사람이 한다 [추정] (2-4) |
| 해결되면 무엇이 달라지나 (측정 가능하게) | ① 거래명세서 1장을 재고에 반영하는 시간: 지금 ___분 → 목표 지금의 절반 이하 ② 입고 기록과 실제 재고가 다른 줄 수 (월 실사 기준): 지금 ___건 → 목표 지금보다 줄임 ③ LLM 판독 결과에서 직원이 고친 줄 비율: 목표 10% 이하. ①②의 지금 값은 클라이언트 미팅에서 확인한다 |
| 핵심 대상과 상태 흐름 | 입고 건: 입고 대기 → 명세서 판독 → 입고 확인중 → 입고 완료 (수량 부족·파손 → 부분 입고 → 공급처 누락 문의 / 검수 중 불량 → 반품 → 반품 완료, 반품 수량만큼 재고 차감) (4-2 A, 3-1 R3·R4) |
| LLM이 하는 일 | 거래명세서 사진·PDF를 읽어 상품명·수량·단가 표로 바꾸고, 발주 내용과 다른 줄을 표시한다. 직원이 실물과 대조해 고친 뒤 확정해야만 재고가 바뀐다. 거래처 담당자 이름·연락처는 LLM에 보내기 전에 가린다 (3-4 L1) |
| 고르지 않은 후보와 그 이유 | B (판매와 재고 불일치): 판매 수량은 POS 숫자라 규칙으로 계산하면 되고 LLM이 할 일이 없다. 상태 흐름도 조사 근거 없이 세웠다 (4-2). C (품절 판단·발주 추천): 추천 수량을 믿으려면 판매 기록이 쌓여야 해서 3주차에 핵심 흐름을 돌리기 어렵다. 입고가 정확해야 품절 판단도 맞으므로 A 다음 단계로 둔다 |
| 이 문제가 실제로 있다는 근거 (카드 번호) | 1-shusbox-2, 3-1 R3 (박스히어로 문서: 입고 처리해야 재고가 바뀌고 부분 입고는 검수로 처리) |
